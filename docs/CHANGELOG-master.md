# NotmyFault 更新日志

## alpha-0.16.0

本版本汇总 alpha-0.15.0 之后的更新，包含 alpha-0.15.1、alpha-0.15.2 和 alpha-0.15.3 开发阶段的改动。

规则编辑统一为节点画布，补救流程直接在图中编排；新增等待、规则结束、目录静默等内置插件，并提供可选的 Dashboard 后台驻留。

**不兼容更新**：规则使用 v2.1 平面图，旧条件树、动作数组和旧插件协议不再读取或转换。符合现行结构、编码、协议和签名要求的数据可以继续使用，具体变化见文末。

### Dashboard：规则编辑与操作逻辑

#### 自由建块与分组

- 统一使用节点画布，移除普通模式和编辑模式切换。选择节点后，在独立的节点设置侧栏中修改参数。
- 在画布空白处右键即可创建触发器、动作、比较条件、逻辑组、IF 事件组、动作组、等待和变量赋值块，不必先接到已有流程上。
- 支持 Ctrl 多选和框选，将选中的图块组合为 IF／ELIF／ELSE、AND、OR 或 NOT 事件组。组合只改变归属，组内连线由用户安排。
- 嵌套组直接在主画布展开、折叠，不再进入独立的 IF 子流程页面。组内节点可以拖入、拖出；改变归属时断开跨组连线。
- 组标题提供类型切换入口，节点复制、删除、组复制及撤销／重做使用同一套图操作。
- 从已有节点或连线插入新图块时，为后续节点及其组内节点留出位置，修复卡片重叠。

#### 连线、分支与数据传递

- 触发器恢复为独立图块，可以直接连接 IF、ELIF、AND、OR 和 NOT。移除中间分支卡片，条件与动作分别连接对应的输入、出口。
- IF／ELIF 按顺序选择首个成立分支；ELSE 保留唯一出口，不接条件。组折叠时只显示已使用的 ELIF，展开后提供下一个备用 ELIF。
- 控制出口、连线和数据输出提供上下文菜单，可以创建后继、在线上插入节点或断开控制连线。
- 从数据输出端口直接创建比较条件、创建变量并赋值，或给已有变量赋值；有多个执行出口时先选择赋值所在的分支。
- 动作组在侧栏中设置对外输出，组外参数通过这些输出引用组内结果。
- 修复拖线、拖动节点时视口突然居中的问题。边缘自动平移、缩放后的端口命中和取消拖动共用画布坐标。
- 调整组展开、侧栏切换和菜单过渡，减少动画设置下保留直接操作反馈。

#### 条件、等待与参数

- 条件编辑支持 ELIF、其他自动化的运行状态、数据存在性及本次运行中的事件发生情况；绑定选择按参数所需类型过滤来源。
- 触发器可选择“事件发生”或“事件未发生”，设置连续未发生时长、判断范围，以及只触发一次或按时间窗口重复触发。
- 事件组可选择立即判断已收到的事件，或等待事件组合成立后再判断，并设置等待超时。
- 等待使用独立图块和专用表单，秒与毫秒可以同时填写；通用插件选择器和快速创建不再重复列出等待动作。
- 参数表达式 JSON 收入可折叠的“高级”区域，展开后直接编辑 `$ref`、`$convert`、`$template` 和 `$literal`。
- 修复大整数输入丢失精度、溢出数字被保存成空值，以及嵌套绑定路径推导类型不准确的问题。
- “规则结束”触发器通过规则列表选择监视目标，显示规则名称和 ID，默认排除自身。
- 修正重复触发设置的读写，界面提供同时运行、运行中忽略、依次排队和取消旧运行执行最新触发四种选择。

#### 测试与运行记录

- 规则测试和局部测试直接使用原图节点与可达路径，支持从指定动作继续或运行到指定节点，并收集所需的前序数据。
- 测试卡片显示事件组的等待过程。取消、超时或完成后更新同一步骤的卡片，清除残留的长时间等待和“正在停止”提示。
- 动作失败后继续观察补救与后续执行，不再把单个步骤失败误当成整次测试已经结束。
- 手动测试包含多个独立触发入口时执行全部入口；共享的汇合节点只执行一次，单个入口失败不会跳过其余入口。
- 修复取消请求晚于运行结束返回时覆盖完成提示、重新显示停止中或弹出错误的问题。
- 运行记录按新的运行状态显示、统计和筛选，增加独立的“已补救”分类；步骤保留原图身份、条件结果、选中分支、等待与恢复、组进入与退出等信息。
- 运行详情显示局部测试范围和补救动作组，可从失败步骤返回对应节点，也可定位补救动作组。
- 修复事件流被普通请求的约 30 秒超时中断，避免长时间测试期间丢失实时更新。

#### 补救流程编辑

- 动作失败处理改为画布上的失败连线和补救动作组，创建、定位、断开与编辑都在同一张图中完成。
- 补救节点可以按普通图块拖动、复制、删除和分组，复杂补救可以折叠为动作组。
- 节点设置保留重试、超时及“补救完成后停止／继续”的选择。选择停止时，补救成功后以“已补救”结束；选择继续时，返回原动作的正常后继。
- 原动作的失败步骤始终保留，补救过程和整次运行结果分别展示。

#### 插件状态与桌面窗口

- 插件页分开显示目录扫描结果与本次引擎会话的加载错误，给出插件 ID、类型和具体原因。
- 元数据无法读取的插件显示“无法读取”，不提供启停和卸载；静态检查不通过的插件显示具体检查原因。
- 引擎离线时说明加载结果尚未确认，读取诊断失败时单独报错，不再显示成零错误。
- 增加“关闭后驻留后台”选项，默认开启。关闭窗口后保留页面，再次打开恢复原窗口；关闭此选项后，关闭窗口退出 Dashboard 进程。
- 驻留选择持久保存，引擎离线时也能修改；从引擎托盘退出时，一并关闭驻留窗口。
- 桌面入口按需加载引擎和通知依赖，本机 HTTP 请求不再读取系统代理或加载 HTTPS 证书存储。
- 生产页面等待桌面桥接就绪后挂载，不再误向静态文件服务请求引擎 API；首页复用已取得的引擎状态。
- 移除重复的“引擎已启动”托盘气泡，保留“NotmyFault 已加载”通知，并将 WinRT 通知创建与发送串行处理。

### 新增内置插件

- **等待 `wait`**：按秒、毫秒暂停当前运行，支持取消和超时。
- **规则结束 `rule_finished`**：在指定规则运行结束后触发另一条规则，可筛选成功、已补救、失败、超时、取消及丢弃或替换等结果。
- **目录静默 `directory_quiescent`**：目录中的匹配文件在指定时长内没有增删改时触发，也可监视重新活跃和状态变化。
- **Wi-Fi 连接 `wifi_connect`**：连接或断开指定网络，并回读连接结果。Windows 使用已保存的网络配置；Linux 使用 NetworkManager，可为新网络提供密码。
- **默认音频设备 `set_default_audio`**：按设备 ID 或名称切换默认播放、录音设备，并回读确认；Windows 同步设置通用、多媒体和通信角色。
- **压缩与解压 `archive`**：创建和解压 ZIP，支持取消，默认保留已有目标文件，并限制解压条目数与总大小。
- **环境变量 `environment_variable`**：读取、设置或删除当前 NotmyFault 进程的环境变量，影响之后启动的子进程，不修改系统或用户级永久配置。
- **Shell 命令 `run_shell`**：在 Linux 通过固定路径的 bash 或 sh 执行命令，支持期限、取消、输出限制和 stderr 错误摘要。

### 规则引擎与运行调度

- 编辑器、API、文件读取、编译、事件匹配和执行统一使用 `workflow.nodes` 与 `workflow.edges`，不再转换为内部条件树或顺序动作数组。
- 执行顺序由显式连线决定。事件组、动作组和嵌套组按图进入、返回，未连入路线的图块不计入实际执行动作数。
- 使用 `RunManager` 调度运行，编译后的规则版本管理触发器实例；每次运行有独立的变量、取消信号和事件观察记录。
- 保存规则后直接应用新版本，按配置指纹复用未变化的触发器，避免无关修改重启全部监听。
- 增加事件消费、事件保留期限和分支选择策略，条件期限使用截止时间堆调度；运行期间收到的事件可用于后续条件判断。
- 等待事件时挂起当前运行并释放动作工作线程，事件或期限到达后恢复，不重复执行等待前的动作。
- 轮询采样使用共享调度线程安排，各实例保留独立配置和状态；触发器、条件计时和规则文件监视使用注入的时钟。
- 崩溃触发器按退避间隔自动重启，并限制连续重启次数；旧实例无法停止时限制恢复重试，避免反复创建实例。
- 规则文件内容检查不再只依赖大小和修改时间。连续写入按最后一次内容变化重新计算防抖时间，相同内容不重复应用。
- 热重载失败后保留现行规则并恢复所需触发器；修复手动运行修改冻结规则、规则改名丢失排队任务，以及旧规则版本的排队执行问题。
- 删除规则时清理最近结果，旧运行的迟到完成不能覆盖同 ID 新规则的结果。
- 修复嵌套条件复用旧分支、布尔值与数字混同比较，以及时间单位换算丢失精度的问题。
- 未处理的工作流异常记录异常类型和原始 traceback，运行结果保留明确的失败码。
- 运行结束增加 `recovered` 与 `run.recovered`。规则结束触发器的“任意”包含已补救，默认的“仅成功”“仅失败”不包含，可单独筛选。
- 宿主事件队列满时丢弃旧事件并继续接收后续事件。退出时主动关闭事件流，先结束插件子进程，再完成服务和托盘清理。
- 修复引擎线程结束后状态不恢复、上一次清理未完成时重新启动，以及状态回调持有启停锁的问题。

### 插件接口与安全

- 公开 `TriggerContext`、实例状态与时钟接口，以及 `RunContext`、`Secret`、`Blob`、`action_values` 和 `system_clock()`，供插件使用运行数据和宿主计时能力。
- 增加引擎事件订阅接口，插件可以直接监听规则运行结束。
- 支持 `poll-v1` 采样工厂，由宿主管理状态变化、重复事件、事件队列、防抖及触发器生命周期。
- 插件加载记录源码摘要，延迟导入和隔离执行复核插件文件；动作、触发器与扩展命令使用经过检查的源码。
- 修复隔离插件覆盖失败后的恢复及扩展会话处理，安装、更新和恢复同步保存用户插件完整性清单。
- 插件元数据类型错误返回具体校验结果，不再导致校验器抛出未处理异常。
- 插件启停统一保存在 `config.disabled_plugins`，内置和用户插件共用；API 返回的 `enabled` 仅为计算后的显示状态。
- 安全模式只保留 `strict` 和 `permissive`。strict 要求加密私钥；permissive 允许缺失或无效签名的插件降级加载，并保留警告。
- 管理员规则审批覆盖补救路线、嵌套组及未连入主流程的有效图块，环境变量写操作纳入规则审批。
- Wi-Fi 密码参数标记为敏感；Linux 通过命令行传递密码时提示其可见性。
- 平台服务增加默认音频设备设置与图片文字识别接口；`recognize_image()` 调用本机 tesseract 识别已有图片。

### 内置插件修复与 Linux 支持

- 电源计划支持 Linux 的 powerprofilesctl；`run_powershell` 明确限定 Windows。
- Linux X11 增加窗口枚举与控制，窗口标题、置顶和窗口控制共用窗口后端。窗口控制依赖 wmctrl、xprop、xdotool 和 xrandr，不支持 Wayland。
- 补充 GNOME／KDE 显示器电源和空闲时间查询、ydotool 套接字查找；缺少 `XDG_SESSION_ID` 时，通过 loginctl 查找锁屏与注销所需会话。
- Linux 电源恢复事件监听 logind `PrepareForSleep(False)`；系统启动身份使用 Linux 启动 UUID 或 Windows 系统启动时间生成。
- 修复 Wi-Fi 配置名称与实际 SSID 不一致、SSID 含空格、引号、冒号或反斜杠时匹配错误，以及查询失败被视为断开的情况。
- Windows 使用 WLAN API 读取实际 SSID；Linux 按配置 UUID 激活连接，固定 nmcli 子进程的状态输出语言，并按所选网卡确认断开结果。
- 修复目录监视、目录静默、USB 等触发器在事件提交失败前就记录状态的问题，失败后仍可再次报告尚未成功提交的变化。
- 修复网络探测停止后继续使用迟到结果，以及规则结束通知重复触发的问题。
- ZIP 压缩遵守 `overwrite`，拒绝覆盖源文件或将压缩包写入源目录；解压检查改写后的路径，限制条目数和总大小，并响应取消。
- 文件动作和路径监视保留路径首尾的空白字符。网络动作修复 DNS 与 TLS 握手期间的取消处理、响应长度校验及失败后的连接清理。
- PowerShell 非零退出时附带 stderr 摘要，Shell 使用固定解释器路径，拒绝空白命令。

- 中断卸载后的用户资源检查改为核对文件内容，确认重试后仍保留用户文件。

### 不兼容变更

#### 规则与配置

- `rules.json` 必须声明 `schema_version: "2.1"` 和 `value_encoding: "typed-v1"`，工作流保存为平面节点与连线。缺失编码、旧结构和未知顶层字段会被拒绝，不进行自动转换。
- 移除规则顶层 `condition`、`event`、`trigger`、`actions`、`preconditions`，以及嵌套的 `then`、`elif`、`else` 和 `failure_actions` 动作数组。
- 移除条件组的 `events` 和 `type: "and"`／`type: "or"` 表达、动作 `id` 与 `steps.<id>` 引用，以及 `{{ path }}` 文本模板。数据引用使用 `$ref`、`$literal`、`$convert` 和 `$template`。
- `config.json` 不再读取 `rules`、`processes`，规则单独保存在 `rules.json`。普通配置不要求规则编码标记。
- 移除用户插件清单 `enabled: false` 到 `disabled_plugins` 的转换，以及配置目录根部 `engine.log` 的旧清理逻辑。

#### 插件与数据声明

- 动作清单必须声明 `execution_api: "context-v1"`，入口为 `run_with_context(action_info, params, context)`；移除两参数 `run(action_info, params)`、`execution_api: "legacy"` 和 `precondition_api`。
- 触发器清单必须声明 `trigger_api: "event-v2"`，入口为 `run(meta, config, emit_event, shutdown_event)`；移除 `event-v1` 和 `trigger_api: "legacy"`。
- `action.json`、`trigger.json` 不接受 `enabled` 字段，包含该字段时校验失败。停用插件改用配置中的 `disabled_plugins`。
- `outputs` 只接受输出字段的对象数组，移除字符串数组等旧声明形式。
- 移除类型别名 `integer`、`boolean`、`list`，以及数组输出的 `item_type` 和参数编辑器的 `accepts_legacy`；数组元素类型使用 `value_type.items`。
- 移除显示器控制的 `low_brightness`、`high_brightness` 操作；文件信息输出使用 `modified_time`，移除 `file_info.modified_at`。

#### 安全与安装

- 移除 `normal` 安全模式，以及 `NOTMYFAULT_MODE` 的 `dev`、`develop` 取值。保留 `alpha` 对应 permissive，`stable`、`master` 对应 strict，环境变量只能提高安全等级。
- 移除 `official-legacy` 和旧签名摘要格式。插件元数据使用 `signature_kind`，不再使用 `signature_source`、`signature_format`；移除 `inspection_report.signature` 和 `sign_plugin` 的 `json_name` 参数。
- 安装器不再识别没有安装标记的旧目录，也不再读取 `installer-build.json`。

- 动作可以配置失败后停止、继续或退避重试。

- 管理员动作和高风险草稿在保存或执行前要求私钥确认。

### 规则与执行引擎

- 配置和规则分别保存到 `config.json` 与 `rules.json`，并继续使用签名、备份和旧格式迁移。
- 规则支持 `event` 单条件和可嵌套的 `condition` 条件树。
- 新增基于 `$ref` 的结构化数据绑定，动作可以读取触发器或前序动作的输出。
- 动作协议新增 `context-v1`，可以读取运行上下文、上一步结果和规则信息。
- 动作取消协议新增 `runtime-v1`，等待中的动作可以响应停止请求。
- 触发器新增 `event-v2`，每个实例拥有独立状态，并按配置指纹匹配事件。
- 新增并发调度器。规则可以限制并发数，并配置重复触发时忽略、排队或重启。
- 新增运行状态和运行记录。引擎会记录排队、执行、取消、失败和完成状态。
- 动作参数与返回值按插件清单生成摘要。敏感字段和未声明字段不会写入运行记录。
- 引擎启动、停止、热重载、触发器线程和扩展会话由独立组件管理。
- 新增隔离动作 worker。插件原生代码崩溃时不再直接带走引擎进程。

### 插件 API 与扩展能力

- 新增整数版本的插件 API v1。
- 插件可以通过公开 API 访问平台能力、通用原生调用锁、网络地址检查和私有数据解包。
- 动作清单支持执行协议、取消协议、幂等性、输出、平台、入口文件、运行模式和安全声明。
- 触发器清单支持事件语义、事件协议、输出、平台和所需能力。
- 新增 `contributes` 扩展协议。插件可以贡献命令、参数编辑器、页面、私有数据类型和窗口控制。
- 插件私有值使用带包名、数据类型和版本的 `plugin_data` 信封保存。
- 新增扩展会话、命令调用、页面消息和插件资源读取。
- 用户插件从源码仓库移到平台配置目录下的 `plugins/`。
- 新增 `.nmfp` 插件包的检查、预览、安装、升级、降级、替换回滚和卸载流程。

- 插件可以声明安装期构建命令和输出文件。安装前会展示构建风险并要求确认。

### 插件与规则安全

- 插件签名改为 Ed25519，并区分内置签名、作者签名和本机确认签名。
- 第三方插件不再接受旧式本地签名。严格模式会在导入插件代码前验证签名和文件清单。
- 完整性清单会检查文件新增、删除和修改，插件物化前还会再次核对全部文件。
- 插件包会拒绝路径穿越、符号链接和目录外文件。
- 安装前使用语法树扫描动态执行、子进程、网络、注册表、文件写入和原生调用。
- 新增借用宿主权限检查。插件不能通过公开 API 获得未声明的管理员、进程或原生能力。
- 管理员代理核对调用模块、函数对象和允许执行的程序名。
- 管理员动作可以要求规则使用私钥确认，并限制必须写成字面量的参数。
- 插件安装和更新使用临时目录与备份。替换失败时恢复旧版本。
- 安全模式分为 strict、normal 和 permissive。构建信息和密钥状态决定启动时采用的模式。

- UIA 选择器和操作宏改用插件私有 `plugin_data`。Dashboard 只提供通用编辑入口。
- README 和开发文档中的失效测试路径已经修正。

### 迁移与不兼容变更

- 旧的 `notmyfault.engine`、`notmyfault.api_server`、`notmyfault.app` 和相关单文件模块已经拆到 `core/`、`host/`、`security/` 与 `platform/`。引用内部模块的代码需要改用新路径或公开插件 API。
- 用户插件目录改为平台配置目录下的 `plugins/`。源码仓库中的 `user_plugins/` 不再是运行时安装位置。
- 规则从配置文件中拆到独立的 `rules.json`。启动时会处理旧格式迁移，迁移后应保留配置目录中的签名和备份文件。
- 第三方插件需要满足新的清单字段、权限、签名和文件完整性检查。旧式本地签名不能继续用于第三方插件。
- 使用 `isolated` 的动作不能声明运行时取消协议，管理员动作也不能使用隔离模式。
- 旧 UIA 动作 `uia_control`、`uia_focus_window`、`uia_read_text`、`uia_wait` 和 `uia_macro` 已移除，不会自动迁移。规则需要改为 `uia_automation` 并重新选择控件或录制操作宏。
- `uia_selector` 不再是宿主参数类型。UIA 数据由 `uia_automation` 插件以 `plugin_data` 管理。
- Linux 支持仍处于实验阶段。Wayland、桌面环境、驱动、权限和外部命令会影响插件可用性。
- Dashboard 构建需要 Node.js 18+；从源码运行仍需要 Python 3.11+。
